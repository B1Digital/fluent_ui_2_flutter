## Behavior and parity notes

Hand-audited behavior that no constructor signature can express. Treat a
documented gap as a real gap: do not describe it as working, and do not
work around it by inventing an API.

- No roving focus. `FluentRadioGroup` installs no `Shortcuts` or `Actions`, and each `FluentRadio` owns its own `FocusNode`, so every radio is a separate tab stop and Arrow keys do not move selection. Official usage and ARIA both expect one tab stop per group with Arrow traversal inside it. Report this rather than emulating it with a hand-rolled key handler on the caller's side.
